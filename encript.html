3 Anti-inspection protections

Applied automatically to every file: right-click disabled, F12/Ctrl+Shift+I/J/C/Ctrl+U/Ctrl+S blocked, text selection & copy disabled, console disabled and cleared, and multi-method DevTools-open detection (docked panels, undocked panels, and a console-open trap).
What this protects against: right-click → View Page Source, Save As, opening the file in a text editor, casual copy-paste, and casual right-click/keyboard shortcuts into DevTools. DevTools detection layers three methods — window-size gap (docked panels), a debugger-timing check (catches undocked/separate-window panels too), and a console-object trap — so it works across Chrome, Edge, and Firefox; Safari's Web Inspector is less consistently caught. The page itself opens and works instantly for every visitor, no login step.

What this cannot protect against, by the nature of browsers: anything actually rendered on screen is, by definition, sitting in the browser's live DOM — so someone determined enough (disabling JavaScript before load, using a proxy/downloader instead of a browser, or a browser these heuristics don't cover) can still get at it, and the embedded decryption key is technically extractable from the loader script. There is no client-side-only technique that closes this gap completely. Treat this as raising the effort required to copy your content a lot — not as real DRM or access control. If actual gatekeeping ever matters, that needs a server in the loop, not a client-only file.
